# Review — r2_formal_methods (Formal Methods / State Machines)

## Summary
Section 3 defines a typed transition system G=(Q,Σ,δ) over seven progress states and four terminal KPI classes, with regression-typed transitions as cycles and cycle depth D as a drift statistic. The engineering instincts are excellent: emitters are named per type, terminal classes are derived from events rather than agent self-reports, the wall-clock (k_cyc) vs turn-count (D) unit split is stated explicitly in Remark rem:drift_trigger, and the abandonment-hazard claim is correctly demoted from lemma to remark. However, two definitional holes are merge-blocking: the compliance-escape class θ_esc is structurally unreachable under the paper's own Table 1, and Definition 2's uniqueness claim is false as stated. A third issue concerns the computability of D under the "either"-typed agent-clarify.

## Score
**6/10.** The formal object is well-motivated and unusually honest about what is a lemma versus a remark, and the unit-discipline remark is exactly what a formal reviewer wants to see. But the section's central claims rest on three definitions that do not hold together as written: a terminal class that no run can reach, a uniqueness argument that would make the paper's own prediction problem trivial if it were true, and a drift statistic whose countability from telemetry is asserted but not operationalized. All are fixable with a few sentences each; none invalidates the program.

## Mandatory revisions
1. **θ_esc is unreachable ⇒ compliance-escape rate is structurally zero (P1).** Table 1 (`sections/03_grammar.tex`, tab:transitions) contains exactly one transition into q_close: `disclosure`, q_confirm → q_close (guarded). `service-complete` fires only from q_close. Therefore every run reaching θ_cont has a prior disclosure, and the audit-overlay condition "reach θ_cont without a prior disclosure transition" (Definition 1, and the dashed edge in fig_grammar.tex) is unsatisfiable. As specified, θ_esc ≡ ∅ and one of the four KPI classes is dead. Fix: either add a disclosure-free path into q_close (e.g., a `user-answer` q_confirm → q_close type, with the guard as a monitor-side predicate), or define the overlay on runs that pass through q_close without the guard having *succeeded*, making explicit which event stream realizes the bypass.
2. **Definition 2 (Run): "unique by absorption" is false and self-undermining (P1).** A partial run σ_{≤j} generally has many well-formed extensions with *different* terminal classes (from q_tool: `hangup`→θ_aban, `escalation`→θ_hand, or continue to θ_cont) — that non-uniqueness is precisely why prediction is needed. Absorption only guarantees finality once T is entered. Reword to: the outcome is the terminal class of the *actual* continuation (final by absorption); among abstract extensions several classes remain reachable, which is what Definition 5's posterior measures.
3. **Definition 3: cycle count is not telemetry-checkable for `agent-clarify` (P1).** The type is "either" (Table 1); whether a given `agent-clarify` increments D depends on it "re-open[ing] a settled state", a semantic judgement the definition does not operationalize — in tension with the section's claim that everything is checkable from telemetry with no human annotation. Fix: state the decidable rule, e.g., a clarify event increments D iff its target state was previously visited and then exited via a progress transition (decidable from the run prefix).

## Optional suggestions
1. Lemma 1's proof says each `tool-call` iteration "adds one LM step and one tool round-trip", but Λ_k uses (k−1)·λ_tool — an off-by-one between proof text and formula. The bound stays valid (under-estimating the gap keeps the violation claim conservative), but k_cyc may be off by one; reconcile with the cited floor arithmetic.
2. Definition 4 writes o_k = (x_k, s_k, e_k, f_k) but then defines each component as a prefix x_{1:k}, etc.; align notation.
3. Definition 5 conditions on turn-indexed o_{1:k}, yet the text claims recomputability "after every event"; either event-index the observation or soften the claim.
4. fig_grammar omits the confirm-side re-open used in Proposition 1's proof, the intent→clarify progress direction, and most "any q_p" hangup/escalation sources; a caption note "subset of Table 1 sources drawn" would prevent misreading.
5. Definition 2's well-formedness clause is vacuous as a property of σ (any δ-permitted run already satisfies it since no type departs from T); the property lives in δ, as the closing sentence itself says.
6. `hangup` from q_close → θ_aban contradicts the operational definition of abandonment ("before any terminal confirmation"); exclude q_close or amend the definition.
7. fig_cycles uses k_dec and A_a (SPRT/LLR notation) not introduced until §4; add "notation of §4" to the caption.

## Questions for authors
1. Which transition type, if any, can enter q_close without a successful `disclosure` guard — i.e., what event stream realizes a non-empty θ_esc?
2. In Λ_k, why (k−1)·λ_tool rather than k·λ_tool — does the final tool round-trip overlap TTS/teardown per garcia2026latencyfloor?
3. For `agent-clarify`, what exact prefix-decidable predicate distinguishes "re-open" (D+1) from "resolving" (no increment)?
