# Review — Reproducibility / Open Science (r10)

## Summary
This is an evaluation-protocol paper evaluated on private Spanish banking call logs, and its honesty about that evidence class is exemplary: §5.7 states plainly that private-log results are not publicly reproducible and frames this as a property of the evidence class, and §8.1 disclaims leaderboard claims while §8.2 ("Data release constraints") honestly admits the synthetic mirror will "dilute the very rare-class structure the protocol targets." The protocol itself is unusually re-runnable on paper: dataset schema fields are enumerated (§5.2), splits are campaign-disjoint, metrics are given as formulas with published anchors (§5.3, e.g., TRACER's τ=0.7788 and EDS/AUC numbers), baselines and ablations are named with predicted directions (§5.5–5.6). However, the artifact promise — the thing a reader will actually get — is a pledge in the future tense without license, version, hashes, generator procedure, cost-model constants, or a compute statement.

## Score
**6/10.** For open science this paper does the hard part (honest evidence-class framing, protocol-level reproducibility) but not the cheap part (a concrete, checkable artifact specification). §5.7 and §9 commit to a "frozen, schema-identical synthetic Spanish benchmark" on Hugging Face and a reference implementation on GitHub, yet nothing pins down what "frozen" and "schema-identical" mean operationally. A reproducibility promise without a license, split manifest, generator spec, or cost-model numbers is aspirational, and this paper is close enough to excellent that closing the gap is mostly one section of work.

## Mandatory revisions
1. **Publish the cost-model constants.** Eq. (\ref{eq:cost_weighted_latency}) in `sections/05_evaluation.tex` (§5.3) defines $\mathcal{L}_{\mathrm{cwd}}$ over $c(\hat\theta,\theta)$ and $\pi_\theta$, but no numeric values are given anywhere ("a false containment costs more than a false handoff" is ordinal, not runnable). The baseline-dominance claim of §5.5 and the false-early-exit economics are unverifiable without them. Add a table (appendix is fine) with the $c$ matrix, $\pi_\theta$, and their provenance (audited deployment accounting?).
2. **Make the artifact commitment checkable (§5.7, §9).** Enumerate the concrete deliverables: HF dataset with schema version, row/call counts, scenario-class taxonomy, terminal-label distribution, **license** (e.g., CC-BY-4.0), and a datasheet; GitHub repo contents (grammar + stopping-rule reference implementation, seeds, configs, baseline training scripts); frozen split manifests with checksums (SHA-256) and a dataset version tag. Currently "frozen" (§5.7) and "release plan of the factory" (§9) have no testable definition.
3. **Specify the synthetic generator and its validation.** §8.2 claims the release "preserves the schema, class structure, and timing distributions of the production corpus" but neither §5.7 nor §8.2 says *how* (template replay? fitted distributions? LLM generation?) or how preservation will be measured beyond "the synthetic-to-private gap is reported" (§5.7). Name the gap metrics (distributional tests per field/class) and state whether the generator code and seeds ship with the dataset.
4. **Add code + compute availability statements.** §5.5 requires retraining "a TRACER-style dual-stream predictor ... on our schema" — a reader needs hyperparameters, backbone, feature spec, or a commitment that configs ship in the repo; TRACER's own public code (noted in OUTLINE) should be cited as the retraining base. Add a compute statement (hardware class, approximate training/inference cost) — currently absent from the entire paper. §9's "any scaling experiments will run in the project's lab environment" should either name the artifact produced or be cut.

## Optional suggestions
1. §5.2: state the split-freeze procedure explicitly (freeze date, hash of campaign partition) so LOCO results are diffable across reruns.
2. §8.2 "restricted access" for the production corpus: one sentence on the access procedure (audit/reviewer NDA route) would make the honesty operational rather than declarative.
3. §5.1 promises inter-annotator agreement "reported" — pre-register the statistic and threshold (e.g., Cohen's κ ≥ x) now.
4. Archive a v1.0 snapshot of the benchmark + paper source with a Zenodo DOI at publication time, consistent with the program's prior Zenodo deposits.

## Questions for authors
1. What license will the HF benchmark carry, and will generator code and seeds be released, or only the generated dataset?
2. What are the numeric values of $c(\hat\theta,\theta)$ and $\pi_\theta$, and were they taken from audited production cost accounting?
3. Will the frozen v1.0 split manifests and their checksums be part of the initial release, or retrofitted after private-side results exist?
